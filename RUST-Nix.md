# Rust and Nix in Otto

This document explains how Rust toolchain management works in this project using Nix flakes.

## Architecture

Otto uses a two-layer approach for Rust development with Nix:

```
┌─────────────────────────────────────────────────────────────┐
│                    rust-overlay (oxalica)                    │
│  Provides: rustc, cargo, rust-std for any Rust version       │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ↓
┌─────────────────────────────────────────────────────────────┐
│                      cargo2nix                               │
│  Provides: Workspace dependency management & package building │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ↓
┌─────────────────────────────────────────────────────────────┐
│                         Otto                                 │
│  Your Rust application built reproducibly with Nix           │
└─────────────────────────────────────────────────────────────┘
```

## Components

### rust-overlay (oxalica/rust-overlay)

- **Purpose**: Provides Rust toolchains (rustc, cargo, rust-std)
- **URL**: `github:oxalica/rust-overlay`
- **What it does**: Makes any Rust version from any channel (stable, nightly, beta) available in Nix
- **Why we need it**: cargo2nix **requires** rust-overlay as a dependency

### cargo2nix

- **Purpose**: Granular builds of Rust projects for Nix
- **URL**: `github:cargo2nix/cargo2nix/release-0.12`
- **What it does**:
  - Generates `Cargo.nix` from your `Cargo.toml` and `Cargo.lock`
  - Provides workspace-level dependency management
  - Creates reproducible builds with granular cacheability
  - Builds development shells with all dependencies
- **Why we need it**: Enables reproducible Rust builds in Nix with proper dependency tracking

## Configuration Files

### `flake.nix`

The main flake configuration that orchestrates both overlays:

```nix
inputs = {
  nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  rust-overlay.url = "github:oxalica/rust-overlay";  # Required by cargo2nix
  cargo2nix.url = "github:cargo2nix/cargo2nix/release-0.12";
  # ...
};

perSystem = { config, pkgs, system, ... }: let
  # Apply BOTH overlays in the correct order
  pkgsWithCargo2nix = import nixpkgs {
    inherit system;
    overlays = [
      cargo2nix.overlays.default    # First: cargo2nix's functionality
      (import rust-overlay)         # Second: Rust toolchain provider
    ];
  };

  # Create the workspace
  rustPkgs = pkgsWithCargo2nix.rustBuilder.makePackageSet {
    rustChannel = "stable";
    rustVersion = "latest";
    packageFun = import ./Cargo.nix;
  };
in {
  devShells.default = rustPkgs.workspaceShell {
    packages = with pkgs; [ pkg-config prek ];
  };
  packages.otto = rustPkgs.workspace.otto {};
}
```

### `Cargo.nix`

Auto-generated by cargo2nix from `Cargo.lock`. **Do not edit manually.**

Regenerate with:
```bash
cargo2nix
```

### `nix/package.nix`

Provides the otto overlay for use in other NixOS configurations. Uses the same overlay pattern as the main flake.

## Common Operations

### Development Shell

```bash
nix develop       # Enter development environment with all dependencies
cargo build       # Build with Cargo (uses Nix-provided toolchain)
cargo test        # Run tests
```

### Building with Nix

```bash
nix build         # Build otto binary using Nix (fully reproducible)
./result/bin/otto # Run the built binary
```

### Updating Dependencies

1. Update `Cargo.toml` and `Cargo.lock` with Cargo:
   ```bash
   cargo add some-dep
   ```

2. Regenerate `Cargo.nix`:
   ```bash
   cargo2nix
   ```

3. Rebuild:
   ```bash
   nix build
   ```

## Why Both Are Required

**TL;DR**: cargo2nix's own flake.nix explicitly declares rust-overlay as a required input.

From [cargo2nix/flake.nix](https://github.com/cargo2nix/cargo2nix/blob/release-0.12/flake.nix):

```nix
inputs = {
  rust-overlay = {
    url = "github:oxalica/rust-overlay";
    inputs.nixpkgs.follows = "nixpkgs";
  };
  # ...
};
```

And later:
```nix
overlays = import ./overlay (rust-overlay.overlays.default);
```

**Do not remove rust-overlay** - cargo2nix will not work without it.

## Test Coverage

This project uses `cargo-llvm-cov` for code coverage measurement.

### Installation

The `cargo-llvm-cov` tool should be installed via cargo:
```bash
cargo install cargo-llvm-cov
```

### Nix Setup

The Nix-provided Rust toolchain via rust-overlay doesn't include the `llvm-tools-preview` component required by `cargo-llvm-cov`. To use coverage with Nix, you have two options:

**Option 1: Use rustup alongside Nix**
```bash
# Install rustup (if not already installed)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Add llvm-tools-preview component
rustup component add llvm-tools-preview

# Run coverage
make test-cov
```

**Option 2: Add fenix to your Nix setup**

Fenix provides Rust toolchains with all components. You can add it to your `flake.nix`:

```nix
inputs = {
  # ... existing inputs
  fenix = {
    url = "github:nix-community/fenix";
    inputs.nixpkgs.follows = "nixpkgs";
  };
};

# In perSystem:
devShells.default = rustPkgs.workspaceShell {
  packages = with pkgs; [
    pkg-config
    prek
    inputs.fenix.packages.${system}.stable.withComponents [
      "cargo"
      "rustc"
      "rust-src"
      "rust-std"
      "llvm-tools"  # Required for cargo-llvm-cov
    ]
  ];
};
```

### Running Coverage

Once `cargo-llvm-cov` is installed and `llvm-tools-preview` is available:
```bash
make test-cov         # Terminal output
make test-cov-html    # HTML report in coverage/
make test-cov-open    # Generate and open HTML report
```

Coverage reports are generated in the `coverage/` directory (automatically ignored by git).
